# TinyTroupe 결과 추출 방법론 (Claude 재현)

## 근거 소스
`extraction/results_extractor.py`, `extraction/normalizer.py`,
`extraction/results_reducer.py`, `extraction/results_reporter.py`,
`extraction/artifact_exporter.py`, `extraction/prompts/*.mustache`

## 개요
자유 발화를 **집계 가능한 형태**로 바꾸는 네 공정: 추출 → 정규화 → 축약 → 보고.
넷을 다 쓸 필요는 없지만, 어느 공정을 쓸지 **트레이스를 보기 전에** 정한다 —
결과를 본 뒤 필드를 만들면 결과에 끌려간다.

---

## 1. 추출 (ResultsExtractor)

1. **추출 목표(objective)를 문장으로 고정한다.** 모호하면 결과도 모호하다.
   예: "이 사람이 A/B 중 최종 선택한 안과 그 이유를 추출하라."
2. **상황(situation)을 명시한다.** 어떤 맥락의 발화였는지 — 판단 범위를 좁힌다.
3. **필드를 고정한다.** 집계할 거라면 필수. 필드마다 값 형식 힌트를 단다.
   예: `preferred_option`(값은 "A" 또는 "B"만), `justification`(한 문장).
4. **트레이스를 읽고 추출한다:**
   - 페르소나별: 그 인물의 THINK/TALK만 근거로 필드를 채운다. 발화에 없는 값은 지어내지
     말고 `null` + "발화 근거 없음"으로 남긴다.
   - 월드 단위: 토론 전체를 하나의 통합 기록(주요 아이디어, 합의점, 이견)으로 요약한다.
5. **집계한다.** 페르소나별 기록을 표나 tally로 모은다 (예: A 2표 / B 1표 + 근거).

---

## 2. 정규화 (Normalizer)

자유 텍스트 항목이 많으면 표현만 다르고 같은 것이 섞인다. **n개 대표 항목으로 병합한다.**

- 목표 개수 n을 먼저 정한다 (예: 반응 14건 → 주제 4개).
- 의미가 같은 항목을 묶고 대표 표현을 정한다.
- **원본 → 대표 매핑을 반드시 남긴다.** 매핑을 버리면 "4개 주제"가 어디서 왔는지 추적할
  수 없다. 이 매핑이 정규화 산출물의 절반이다.
- 같은 대상을 다시 정규화할 때는 앞선 매핑을 재사용해 일관성을 유지한다.

---

## 3. 축약 (ResultsReducer)

트레이스를 표로 바꾼다. **트리거마다 축약 규칙을 등록**한다.

```
트리거: TALK 행동  → 규칙: (발화자, 대상, 한 줄 요약, 단계)
트리거: 자극 수신  → 규칙: (수신자, 자극 종류, 내용 요약)
```
등록한 규칙에 걸리는 항목만 표에 들어간다. 나머지는 버려진다 — 무엇을 버렸는지 적는다.

---

## 4. 보고 (ResultsReporter)

보고서는 세 경로로 만든다. 어느 경로인지 명시한다.

| 경로 | 방법 | 특징 |
|---|---|---|
| **인물 인터뷰** | 페르소나에게 직접 질문해 답을 받아 보고서로 엮는다 | 트레이스에 없던 정보가 나온다 — 그래서 **새로운 시뮬레이션**이지 추출이 아니다. 그렇게 표기한다 |
| **상호작용 기반** | 트레이스 전체를 보고 요건에 맞춰 서술 | 추출의 서술형 |
| **원자료 기반** | 이미 구조화된 데이터에서 서술 | 집계 결과의 해설 |

인물 인터뷰 경로는 강력하지만 **추출과 섞지 않는다.** 추출은 있는 발화만 근거로 하고,
인터뷰는 새 발화를 만든다.

---

## 5. 산출물 저장 (ArtifactExporter)

- 산출물마다 **이름 규약**을 정한다: `{대상}.{작성자}` 또는 단계 번호.
- 같은 내용을 여러 형식으로 낼 때(마크다운 + 구조화 데이터) **같은 이름을 쓴다.**
- 이 팀에서 파일 저장은 리드가 한다. 워커는 무엇을 어떤 이름으로 남길지만 제안한다.

---

## 산출 형식

```json
{
  "agent_extractions": {
    "Lisa":  {"preferred_option": "A", "justification": "..."},
    "Oscar": {"preferred_option": null, "justification": "발화 근거 없음"}
  },
  "world_extraction": {"주요_주제": ["..."], "합의": "...", "이견": "..."},
  "normalization": {"대표항목": ["..."], "매핑": {"원본1": "대표1"}}
}
```
파일로 저장할 때는 트레이스 옆에 `*.results.json`으로 둔다.

## 경계
- 모든 결과에 **SIMULATED(시뮬레이션)** 표기를 유지한다. 실제 설문·통계로 제시 금지.
- 추출은 트레이스에 있는 발화만 근거로 한다. 트레이스 밖 추론으로 필드를 채우지 않는다.
- 정규화로 묶은 것을 "합의"라고 부르지 않는다 — 표현이 비슷한 것과 의견이 같은 것은 다르다.
- 집계 수치를 모집단으로 일반화하지 않는다 ([[tinytroupe-experiments]] §2).
