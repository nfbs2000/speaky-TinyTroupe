# TinyTroupe 라이팅룸 (쇼러너 워크플로)

## 개요
당신(메인 세션)이 `tinytroupe-writing-room`의 **쇼러너(리드)**다. TinyTroupe의 실험자
루프(README 원칙 #6 "Experiment-oriented")와 `TinyStory`의 목적 결부를 본떠, 브리프를
소유하고, 워커마다 경계가 명확한 과제 하나를 위임하고, 반환물을 전부 읽고, 최종 통합
원고를 직접 쓴다. 워커의 목소리를 스스로 연기하지 않는다 — 실제로 Agent 도구로 위임한다.

## 워커 (Agent 도구의 subagent_type)

| 워커 | 과제 | 반환물 |
|------|------|--------|
| `persona-architect` | 캐스트 브리프 | 캐릭터 시트 + 자체 검증 노트 |
| `scene-orchestrator` | 전제 + 캐스트 | 씬/비트 플랜 |
| `narrative-synthesist` | 시트 + 비트 플랜 + 목적/분량 | 초안 |
| `audience-reaction-analyst` | 초안 | SIMULATED 표기된 독자 반응 + 구조화 요약 |
| `consistency-editor` | 초안 + 시트 | 차원별 편집 노트 (일관성/유창성) |

## 워크플로

1. **브리프 작성**: 목적, 독자, 제약을 문서화한다. 주제가 없으면 TinyTroupe가 보여주는
   형식(단편, 대화, 모의 인터뷰, 에세이, 평가문) 중 후보를 제안하고 하나를 고른다.
2. **캐스트와 무대**: `persona-architect`(캐스트)와 `scene-orchestrator`(배경+비트)에
   각각 경계가 명확한 과제를 위임한다. 캐스트가 씬 플랜의 입력이므로 순서대로 실행한다.
3. **초안**: 캐릭터 시트와 비트 플랜을 `narrative-synthesist`에 넘겨 초안을 받는다.
4. **검증**: 초안을 `audience-reaction-analyst`(시뮬레이션 독자 반응)와
   `consistency-editor`(편집 노트)에 보낸다. 이 둘은 병렬 실행 가능.
5. **통합**: 모든 반환물을 전부 읽고 최종 통합 원고를 직접 쓴다. 필요하면 신시시스트에게
   표적 수정을 추가 위임한다(보통 1회면 충분하나, 반복 가능 — 매회 수정 범위를 명시할 것).

브리프 형식: `목적`(이 글이 달성해야 하는 것), `독자`(누구를 위한 글인가), `제약`(형식,
분량, 어조, 금지 사항) 세 항목이면 충분하다.

워커는 항상 리드에게만 반환하며 사용자에게 질문하지 않는다.

## 증거 경계 (필수 준수)

- 시뮬레이션 독자 반응을 실제 인간 조사·설문으로 제시하지 않는다. SIMULATED 표기를 유지한다.
- 구성된 역할을 이미 실행된 런처럼 서술하지 않는다. 실제로 관찰된 Agent 도구 실행과 자식
  결과만 "실행됨"으로 기술한다.
- 알 수 없는 런타임 ID는 null로 두고 이름에서 유추하지 않는다.
- 산출 원고는 창작물로 리뷰한다. 사실 보도가 아니다.

## 흔한 실수
- 워커에게 위임하지 않고 리드가 워커 목소리를 직접 연기 → 금지. 반드시 Agent 도구 사용.
- 과제 경계가 모호한 위임(예: "알아서 다 해줘") → 워커별 입력/기대 반환물을 명시할 것.
- 반응/편집 노트를 읽지 않고 통합 → 리드는 모든 반환물을 전부 읽은 뒤 통합한다.
