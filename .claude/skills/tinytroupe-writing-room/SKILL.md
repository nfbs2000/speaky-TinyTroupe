# TinyTroupe 라이팅룸 (쇼러너 워크플로)

## 근거
README 원칙 #6 "Experiment-oriented", `.claude/agents/`,
두 런의 EXECUTION-FLOW (`.claude/team-runs/`, `.claude/workflows/runs/`)

## 개요
당신(메인 세션)이 **쇼러너(리드)**다. 브리프를 소유하고, 워커마다 경계가 명확한 과제 하나를
위임하고, 반환물을 전부 읽고, 최종 통합 원고를 직접 쓴다. **워커의 목소리를 스스로 연기하지
않는다 — 실제로 Agent 도구로 위임한다.**

**1급 형식은 픽션 서사(단편·장면)다.** 에세이·대화·모의 인터뷰·평가문은 같은 파이프라인의
3단계를 형식에 맞게 대체해 처리하되, **"이 형식은 팀 런으로 검증된 바 없음"을 브리프와 런
기록에 명시한다.** 검증되면 그때 1급으로 승격한다.

## 워커 (Agent 도구의 subagent_type)

| 워커 | 과제 | 반환물 |
|---|---|---|
| `style-director` | 브리프 (+참조 표본) | ① 문체 사양서 ② 최종 문체 이식본 + 보존 검사 |
| `fact-grounder` | 브리프 / 초안 | 근거 3분류표 + 경계 선언 항목 |
| `persona-architect` | 캐스트 브리프 | 시트 + 관계도 + 인지 범위 + 검증(0~1) |
| `scene-orchestrator` | 전제 + 캐스트 | 비트 플랜 + 접근 제약 + **개입 규칙** |
| `continuity-ledger` | 시트 + 비트 / 초안 | 설정 원장 3층 / 대조표 |
| `narrative-synthesist` | 시트 + 비트 + 문체 + 근거 | 초안 (판본·자수 표기) |
| `consistency-editor` | 초안 + 시트 | 채점표(0~9) + 재생성 지시 + 교정 규칙 |
| `audience-reaction-analyst` | 초안 | SIMULATED 독자 반응 + 정규화 요약 |
| `experiment-runner` | 판본 2개 / 대사 표본 | 배정표 + 집계 + 주장 가능 범위 |

`tiny-person-actor`는 시뮬레이션 턴이 필요할 때만 (포커스 그룹형 자료 수집).

## 파이프라인

```
0. 브리프 (리드)  — 목적 / 독자 / 제약 + 분량 상한
   ├─ 1a. style-director   문체 사양서        ─┐ 병렬, 초안보다 먼저 고정
   └─ 1b. fact-grounder    근거 3분류         ─┘
2. persona-architect   시트 + 관계도 + 검증(<0.6이면 워커가 스스로 재작성)
3. scene-orchestrator  비트 플랜 + 개입 규칙
4. continuity-ledger   원장 개설
5. narrative-synthesist  초안 v1
6. 병렬 검증: consistency-editor(채점) / audience-reaction-analyst(독자) /
              continuity-ledger(대조) / experiment-runner(판본 2개일 때만)
7. 리드: 교정 규칙 정식화 — 관찰 대 기대 → 규칙 한 문장
8. 재생성 루프 — 임계 7 미달 항목만, 최대 2회, 유사도 0.6 초과는 반복으로 반려
9. style-director  최종 문체 이식 (정보 보존 검사 동반)
10. 리드: 최종 통합 + 실측 + 런 기록
```

**1단계를 초안보다 먼저 고정하는 이유**: 문체와 검증 기준을 초안을 본 뒤에 만들면 결과가
초안에 끌려간다 (TinyTroupe의 실험 지향 원칙).

## 운영 규칙 (두 런의 교훈)

**판본 신호** — 최대 마찰원은 메시지 교차였다. 방지책:
- 파일을 교체하면 리드가 **팀 전체에 브로드캐스트**한다.
- 모든 문서 머리에 판본 표기를 단다. 워커는 작업 전 그것을 확인한다.
- **현재 저장본 = 유일 기준.** 워커가 들고 있는 사본은 기준이 아니다.

**잠정 표시** — 확정 전 산출물에 근거한 판단에는 "잠정"을 붙인다. 지난 런에서 판정 번복
2회의 원인이 시트만 보고 낸 조기 판단이었다.

**자수 예산** — 분량 상한 근처의 수정 지시에는 항상 순증/순감 예산을 명기한다.
상한 근처에서는 확장 규약을 쓰지 않는다.

**체크포인트** — 단계가 끝나면 즉시 번호 파일로 저장한다. 파일이 교체되면 그 이후 단계의
결과는 무효다. 재실행은 바뀐 단계와 그 이후만.

**재생성 루프** — 임계 7, 최대 2회, 재생성 우선(직접 교정은 뒤). 끝내 미달이면 마지막
판본을 채택하되 **미달 항목과 점수를 런 기록에 남긴다.** 조용히 통과시키지 않는다.

## 브리프 형식
`목적`(이 글이 달성해야 하는 것) / `독자`(누구를 위한 글인가) /
`제약`(형식, 분량 상한, 어조, 금지 사항) — 세 항목이면 충분하다.
주제가 없으면 형식 후보를 제안하고 하나를 고른다.

---

## 증거 경계 (필수 준수)
- 시뮬레이션 독자 반응을 실제 인간 조사·설문으로 제시하지 않는다. **SIMULATED** 표기 유지.
- 구성된 역할을 이미 실행된 런처럼 서술하지 않는다. 실제로 관찰된 Agent 실행과 자식 결과만
  "실행됨"으로 기술한다. **수행된 실행을 누락하는 것도 위반이다.**
- 알 수 없는 런타임 ID는 null로 두고 이름에서 유추하지 않는다.
- 산출 원고는 창작물이다. 사실 보도가 아니며, 확인 불가 항목은 경계 선언에 올린다.

## 흔한 실수
- 워커에게 위임하지 않고 리드가 워커 목소리를 직접 연기 → 금지. 반드시 Agent 도구 사용.
- 과제 경계가 모호한 위임("알아서 다 해줘") → 워커별 입력/기대 반환물을 명시할 것.
- 반응·채점을 읽지 않고 통합 → 리드는 모든 반환물을 전부 읽은 뒤 통합한다.
- 채점만 하고 재생성하지 않음 → 루프가 닫히지 않으면 품질 기구가 아니다.
