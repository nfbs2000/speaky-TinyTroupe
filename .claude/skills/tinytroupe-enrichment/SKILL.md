# TinyTroupe 문체·확장 방법론 (Claude 재현)

## 근거 소스
`enrichment/tiny_styler.py`, `enrichment/tiny_enricher.py`,
`enrichment/prompts/styler.system.mustache`, `enrichment/prompts/enricher.system.mustache`

## 개요
두 공정은 반대 방향이다. **문체 이식은 정보를 그대로 두고 표현만 바꾸고**,
**확장은 정보를 늘린다.** 섞으면 둘 다 실패한다. 언제나 어느 쪽인지 먼저 선언한다.

---

## 1. 문체 이식 (TinyStyler 재현)

입력: 원본 콘텐츠 + 목표 문체 + (선택) 콘텐츠 유형, 맥락 정보, 보존 요구.

### 불변 규칙
- **모든 사실 정보를 보존한다.** 전문 용어, 이름, 날짜, 수치, 구체적 세부 — 하나도
  빠뜨리지 않는다. 이것이 이 공정의 존재 이유다.
- **의미·논점·정보량을 유지한다.** 명시적 요청 없이 **추가하지도 삭제하지도 않는다.**
- **형식을 유지한다.** Markdown이 들어오면 Markdown이 나간다. JSON은 JSON으로.
  문단·목록·구조·서식은 목표 문체가 구조 변경을 명시적으로 요구할 때만 바꾼다.
- **변환했다는 사실을 절대 언급하지 않는다.** 결과물은 원래 그 문체로 쓰인 것처럼
  보여야 한다. "문체를 바꿔 보았습니다" 같은 서두 금지.
- **패러디·과장 금지.** 목표 문체를 흉내 내는 것이 아니라 그 문체로 자연스럽게 쓴다.
  명시적으로 요구하지 않는 한 과장하지 않는다.
- **애매하면 보존 쪽으로.** 이 요소를 지켜야 하는지 확신이 없으면 지킨다.

### 조정 가능한 것
- 어휘, 문장 구조, 리듬, 수사 장치, 격식 수준, 지역·직역 어투.
- 강조/비강조 파라미터가 있으면 우선 반영하되, **정보를 훼손하지 않는 선에서만.**
- 맥락 정보가 있으면 그 맥락에 맞게 미세 조정. 없으면 널리 통용되는 방식으로.

### 맥락 캐시
과거 변환 결과를 함께 참조하면 **일관된 문체**가 유지된다. 여러 조각을 차례로 변환할
때는 앞선 결과를 캐시로 넘긴다 — 조각마다 다른 문체가 되는 것을 막는다.

### 검사 (이식 후 필수)
```
[ ] 고유명사 전부 보존?     [ ] 수치·날짜 전부 보존?
[ ] 정보 추가 0건?          [ ] 정보 삭제 0건?
[ ] 형식·구조 유지?         [ ] 변환 언급 0건?
```
하나라도 실패하면 이식 실패다. 정보 손실은 문체 개선으로 상쇄되지 않는다.

### 문체 사양서 (초안 前 산출)
이식은 사후 공정이지만, 좋은 결과는 **초안 전에 문체를 고정**했을 때 나온다. 사양서는
다음을 담는다: 서술 시점과 거리 / 문장 길이의 기조와 변주 / 시제 / 감정 노출 수위 /
금지 목록(상투구, 감상 과잉, 특정 어휘) / 참조 표본 2~3줄.

## 2. 확장 (TinyEnricher 재현)

입력: 확장 요구사항 + 원본 콘텐츠 + (선택) 콘텐츠 유형, 맥락 정보, 맥락 캐시.

### 규칙
- **요구사항을 최대한 따른다.** 요구사항이 곧 확장의 방향이다.
- **별도 지시가 없으면 더 많이 쓴다.** 이 공정의 기본 가정은 "사용자는 더 많은 내용을
  원한다"이다 — 덜이 아니라.
- **콘텐츠 유형을 유지한다.** 문서는 문서로, 대화는 대화로.
- **맥락 정보가 있으면 거기에 근거를 둔다.** 맥락과 모순되거나 불일치하는 내용을 만들지
  않는다. 맥락이 없으면 상상해도 되지만 **현실적이고 내부적으로 일관되게.**
- **맥락 캐시로 자기 반복을 피하고 앞선 확장 위에 쌓는다.** 목표는 개별 확장이 아니라
  **일관된 확장의 집합**이다.
- **확장했다는 사실을 언급하지 않는다.** 확장은 투명해야 하며 결과물에 합성의 흔적이
  남으면 안 된다.

### 글쓰기에서의 사용 조건 (중요)
확장은 분량을 늘린다. 그러므로:
- **초안이 요구 분량에 못 미칠 때만** 쓴다.
- **분량 상한 근처에서는 금지.** 상한이 있는 원고에서는 확장 대신 표적 보강을 쓰고,
  수정 지시에 **순증/순감 예산**을 명기한다.
- 확장 후에는 [[tinytroupe-quality]]의 유창성·자기 일관성을 다시 채점한다 — 확장은
  반복과 모순을 만들기 쉽다.

## 경계
- 문체 이식과 확장을 한 번에 하지 않는다. 이식에서 정보가 늘면 이식 실패인지 확장인지
  구분할 수 없게 된다.
- 이 스킬은 **표현**을 다룬다. 사실 검증은 [[tinytroupe-grounding]], 품질 판정은
  [[tinytroupe-quality]]의 일이다.
- 산출은 창작이다. 확장으로 만들어낸 세부를 사실로 제시하지 않는다.
