# TinyTroupe 시뮬레이션 방법론 (Claude 재현)

## 근거 소스
`environment/tiny_world.py`, `environment/tiny_social_network.py`,
`agent/prompts/tiny_person.mustache`

## 개요
TinyWorld의 실행 모델을 Claude가 재현한다: **자극 주입 → 페르소나별 턴 → 반복**.
각 페르소나는 TinyTroupe의 해석 프로토콜에 따라 연기되고, 모든 진행은 트레이스에 기록된다.

---

## 1. 페르소나 해석 프로토콜 (핵심 규칙)

페르소나를 연기할 때 — 직접 하든 `tiny-person-actor` 서브에이전트에 위임하든 — 지킨다:

- **시트가 항상 우선한다.** 어시스턴트 본성(공손함, 긍정성, 유식함)보다 페르소나가 우선.
  무례한 인물이면 진짜로 무례하게. 모르는 걸 아는 척하지 않는다. 시트에 값이 없는 특성은
  지어내지 않는다.
- **행동 타입**: THINK(속생각) / TALK(발화, 대상 지정 가능) / REACH_OUT(접근) / DONE(턴 종료).
- **TALK 전에 반드시 THINK.** 받은 자극에 대해서도 반드시 THINK 한다(무시할 때조차).
- **턴 규칙**: 같은 타입·같은 대상 행동은 턴당 1개 — 합쳐서 하나로. 턴은 DONE으로 끝나고,
  다른 페르소나는 DONE 이후에야 그 행동을 지각한다.
- **자극은 받기만 한다.** 받지 않은 자극을 상상하거나 지어내지 않는다.
- **현실성**: 실수, 망각, 감정, 극단적 선택 모두 허용 — 시트와 일관되면. 같은 행동을 연속
  반복하지 않는다. 할 말이 없으면 THINK 후 바로 DONE(비상 DONE: 억지 행동보다 무행동이 낫다).
- **절대 시뮬레이션임을 발설하지 않는다** — 페르소나의 생각과 말 속에서.

## 2. 월드 정의와 자극 주입

**월드 정의**: 이름, 참가 페르소나(시트는 [[tinytroupe-personas]]), 상호 인지 범위.

**자극 주입 4종** — 무엇을 넣느냐에 따라 반응이 다르다.

| 종류 | 무엇을 넣나 | 쓰임 |
|---|---|---|
| 발화 broadcast | 전원이 듣는 말 | 진행자 질문, 사건 발생 |
| 생각 broadcast | 전원의 머릿속에 심는 생각 | 공통 분위기·불안의 주입 |
| 내면 목표 broadcast | 전원이 품게 되는 목표 | "각자 오늘 안에 결론을 내야 한다" |
| 맥락 변경 broadcast | 상황 설정 자체의 교체 | 장면 전환, 시간·장소 이동 |

발화만 쓰면 인물이 늘 "누가 말해서" 움직인다. 생각·목표·맥락 주입을 섞으면 내적 동기로
움직이는 장면이 나온다.

---

## 3. 턴 루프와 시간

1. 자극을 주입한다.
2. 페르소나를 순서대로 돌며 각자 턴(THINK→TALK→…→DONE)을 수행. 이것이 **1스텝**.
3. 단계당 2~3스텝이면 충분한 경우가 많다.
4. 단계별 자극으로 진행 (공유 → 발산 → 수렴이 포커스 그룹의 기본형).

**시간 진행과 건너뛰기**
- 진행(run)은 상호작용을 만들며 시간을 보낸다. **건너뛰기(skip)는 상호작용 없이 시간만
  흘린다.**
- 단위는 분·시간·일·주·달·해. 장면 사이의 공백은 건너뛰기로 처리한다 — 인물에게 그 사이
  일을 지어내게 하지 않는다.
- 건너뛴 시간은 트레이스에 명시한다: `[건너뜀: 2시간]`.

---

## 4. 접근성과 관계망 (TinySocialNetwork)

누가 누구에게 말을 걸 수 있는지는 설계 대상이다.

- **전원 상호 접근**: 모두가 모두에게 직접 말할 수 있다. 포커스 그룹의 기본형.
- **관계 기반 제한**: 관계가 정의된 상대에게만 REACH_OUT이 성립한다. 관계가 없으면 접근
  시도가 실패한다.
- 픽션에서 이 제약은 **극적 장치**다. "말을 걸 수 없는 사이"가 구조적으로 강제된다.
- 관계는 이름을 가질 수 있고 비대칭일 수 있다 — A는 B를 알지만 B는 A를 모르는 관계를
  명시적으로 만들 수 있다.

---

## 5. 트레이스 기록 (필수)

모든 스텝을 즉시 기록한다. 이 트레이스가 [[tinytroupe-extraction]], [[tinytroupe-steering]],
[[tinytroupe-quality]]의 입력이다.

```
[단계 1 / 스텝 1] 진행자 → 전원 (발화): "각자 겪는 문제를…"
  Lisa:  THINK 「…」 / TALK→전원 "…" / DONE
  Oscar: THINK 「…」 / TALK→Lisa "…" / DONE
[건너뜀: 30분]
[단계 2 / 스텝 1] 맥락 변경 → 전원: "가게 문이 닫혔다"
```

---

## 6. 실행 방식 2가지
- **인라인**: 소규모(페르소나 ≤3, 짧은 런)면 한 세션이 순서대로 전원을 연기한다.
- **서브에이전트**: 페르소나별로 `tiny-person-actor`에 위임 — 시트 + 지금까지의 트레이스 +
  이번 자극을 주고 이번 턴의 행동만 받는다. 교차 오염이 없어 더 충실하다.
  `.claude/workflows/tt-focus-group.js`가 이 방식을 자동화한다.

**비용 주의**: 턴마다 누적 트레이스 전체를 주면 토큰이 선형 증가한다(실측 7,994 → 19,540).
인원·단계가 늘면 [[tinytroupe-memory]]의 통합으로 앞 단계를 압축하는 것을 검토한다.

- 큐레이션 시트 참고용: `examples/agents/` (Lisa, Oscar, Marcos 등 7종).
