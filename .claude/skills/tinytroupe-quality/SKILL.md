# TinyTroupe 품질 방법론 (Claude 재현)

## 근거 소스
`experimentation/proposition.py`, `validation/propositions.py`,
`agent/action_generator.py`, `utils/semantics.py`, `utils/behavior.py`,
`validation/validation_chamber.py`

## 개요
품질 관리는 네 부분이다: **무엇을 재는가(명제)** → **어떻게 채점하는가(규약)** →
**미달이면 무엇을 하는가(루프)** → **같은 지적이 반복되지 않게 하는 법(교정 규칙)**.
노트만 주고 끝내면 품질 기구가 아니다. 루프가 닫혀야 한다.

---

## 1. 채점 규약 (Proposition 재현)

명제는 **대상에 대한 주장 한 문장**이다. 대상은 트레이스, 초안, 인물, 혹은 그 목록.

- **점수 범위는 0~9.** 불리언 판정(참/거짓)과 점수 판정을 구분해서 쓴다. 통과 여부만
  필요하면 불리언, 개선 여지를 보려면 점수.
- **산출 4종을 반드시 함께 낸다:**
  | 항목 | 내용 |
  |---|---|
  | 값 | 점수(0~9) 또는 참/거짓 |
  | 근거 | 왜 그 값인가 — 대상의 구체적 위치를 인용 |
  | 확신도 | 이 판정을 얼마나 믿는가 (0~1) |
  | 개선 권고 | 점수를 올리려면 무엇을 바꿔야 하는가 |
  근거 없는 점수는 무효다. 확신도가 낮으면 그 판정으로 재작업을 지시하지 않는다.
- **판단 창(window)을 정한다.** 긴 트레이스는 전체를 보면 판정이 흐려진다. 기본값은
  **앞 5개 + 뒤 10개**. 창을 좁힐수록 판정이 날카로워진다.
- **이중 확인(double check).** 판정 후 "정말 그런가"를 한 번 더 묻으면 더 엄격해진다.
  느리므로 고위험 판정(최종 승인, 삭제 권고)에만 쓴다.
- **전제조건.** 적용 대상이 아닌 경우 명제는 **자동 참**으로 처리한다(`전제 → P`).
  예: "발화의 유창성" 명제는 DONE 행동에는 적용되지 않는다 → 자동 참.
- **시트 포함 여부.** 페르소나 준수 판정에만 캐릭터 시트를 맥락에 넣는다. 자기 일관성·
  유창성 판정에는 넣지 않는다 — 시트를 보면 판정이 오염된다.

## 2. 표준 명제 세트

소스의 명제를 그대로 쓴다. 필요한 것만 골라 쓰되, 고른 목록을 **채점 전에 고정**한다.

### 인물 속성

| 명제 | 주장 | 채점 규칙 |
|---|---|---|
| **페르소나 준수** | 행동이 시트와 일치한다 | 성격·스타일·신념·행동·기술 5기준을 **동등 가중 평균**. 트레이스 전체 행동의 평균 |
| **페르소나 준수(엄격)** | 시트와 모순되는 것이 하나도 없다 | **결함 1건당 20% 감점**, 경중 불문. 최종 승인 직전에만 |
| **자기 일관성** | 자기모순이 없다 | **행동만** 본다. 시트·자극·배경은 무시. 선행 행동이 없으면 자동 참 |
| **유창성** | 반복·상투·기계적 어투가 없다 | 같은 생각·표현의 반복, 공식적 어투, 인간답지 않은 문장을 감점 |
| **적합성** | 상황·과제·목표에 맞는다 | 3조건 중 **하나만** 충족해도 만점 — ① 옳은 방향의 합리적 한 걸음 ② 관련 정보 산출 ③ 최근 자극에 대한 합당한 반응. 소스에서는 기본 꺼짐 |
| **과제 완수** | 주어진 과제를 끝냈다 | 과제 서술을 변수로 받는다. 논의·사고·행동·특정 행동 변주·기타 요구를 각각 확인 |
| **최근 침묵** | 연속 DONE으로 조용하다 | 마지막 2개 이상이 연속 DONE. 개입 트리거로 쓴다 |

### 환경 속성

| 명제 | 주장 | 글쓰기에서의 쓰임 |
|---|---|---|
| **분화(divergence)** | 진행될수록 인물들이 **서로 달라진다** — 생각·말·행동·주제가 다양해진다 | **목소리 분화의 척도.** 픽션에서 인물이 서로 닮아가면 실패다 |
| **수렴(convergence)** | 진행될수록 인물들이 **서로 닮아간다** — 하나의 주제·관점으로 모인다 | 합의를 목표로 한 토론에서는 이쪽이 성공 신호 |

두 명제는 반대다. **어느 쪽을 원하는지 먼저 선언하고** 그에 맞는 명제를 채점한다.

## 3. 재생성 루프 (ActionGenerator 재현)

```
산출 생성 → 채점 → 임계 미달? ─아니오→ 채택
                    │
                   예
                    ↓
            재생성 (최대 2회)
                    │
              여전히 미달?
                    ↓
        마지막 시도본 채택 + 미달 항목 명시
```

- **임계는 7** (0~9 기준). 항목 **전부**가 임계를 넘어야 통과다 — 평균이 아니다.
- **최대 시도 2회.** 무한 루프 금지.
- **재생성이 우선, 직접 교정은 뒤.** 소스에서 직접 교정은 기본 꺼짐이고
  "아직 잘 작동하지 않음"으로 표시돼 있다. 산출자에게 다시 만들게 하는 쪽이 낫다.
- **끝내 미달이면 마지막 판본을 채택한다.** 가장 많이 다듬어진 판본이기 때문이다.
  단, **미달 항목과 점수를 런 기록에 남긴다.** 조용히 통과시키지 않는다.
- **통계를 기록한다**: 총 시도 수, 재생성 실패 수, 원본(1차 시도) 통과율. 이 숫자가
  다음 런의 임계·창 조정 근거가 된다.

### 재생성 지시 형식
재생성을 요청할 때는 항목별로 이렇게 준다:

```
[미달] 유창성 5/9 (확신도 0.8)
근거: 3~5문단에서 "그러나"로 시작하는 문장이 연속 3회
권고: 접속 구조를 바꾸거나 문장을 합칠 것
예산: 순증 0자 (분량 상한 근처)
```

## 4. 반복 차단 (Jaccard 유사도)

새 산출이 직전 산출의 자기 표절인지 기계적으로 본다.

- **타입이나 대상이 다르면 유사도 0** — 비교하지 않는다.
- 같으면 내용의 **Jaccard 유사도**(교집합 ÷ 합집합)를 본다.
- **0.6을 넘으면 반복으로 간주**하고 반려·재생성한다.
- 글쓰기에서의 적용: 같은 인물의 연속 대사, 반복되는 묘사 패턴, 장면마다 재등장하는
  같은 비유. 정확한 계산이 아니어도 "어휘의 절반 이상이 겹치는가"로 판단할 수 있다.

## 5. 교정 규칙 정식화 (semantics 재현)

같은 지적이 반복되면 피드백이 규칙이 되지 못한 것이다. 3단계로 승격시킨다.

**1) 관찰 대 기대로 재구조화**
피드백을 두 줄로 쪼갠다.
```
관찰된 것: 세 인물이 모두 짧은 단문으로 말한다
기대된 것: 시트상 윤경아는 말끝을 흐리고 서동만은 문장을 끝까지 맺는다
```

**2) 교정 규칙 한 문장 뽑기**
그 격차에서 **일반 규칙**을 만든다. 이번 사례가 아니라 다음번에도 쓰일 문장으로.
```
규칙: 인물의 발화 길이와 종결 방식은 시트의 말투 항목에서 직접 도출한다.
      세 인물이 같은 리듬으로 말하면 시트를 다시 읽는다.
```

**3) 다음 산출을 규칙에 비추어 교정**
규칙 목록을 다음 판본의 입력으로 넘긴다. 규칙은 누적된다 — 런 내내 유지되는 원장이다.

> 이 절차가 Gazpacho "with behavior correction" 노트북의 실체다. 노트를 규칙으로
> 승격시키지 않으면 매 판본마다 같은 말을 반복하게 된다.

## 산출 형식

```
## 채점 (판본: v2, 2026-08-04 14:20 저장본)
| 명제 | 점수 | 확신도 | 근거 | 권고 |
|---|---|---|---|---|
| 페르소나 준수 | 8/9 | 0.9 | ... | ... |
| 자기 일관성 | 6/9 | 0.7 | ... | ... |  ← 미달

## 교정 규칙 (누적)
R1. ...
R2. ...

## 루프 상태
1차 시도 통과 2/5 · 재생성 1회 · 미달 잔여 0건
```

## 경계
- 채점은 **기교와 일관성**에 대한 것이다. 내용이 사실인지 보증하지 않는다 — 사실 근거는
  [[tinytroupe-grounding]]의 일이다.
- 근거 없는 점수, 확신도 없는 판정을 내지 않는다.
- **잠정 표시**: 확정 전 산출물(중간 판본, 시트만 보고 낸 판단)에 근거한 채점에는 "잠정"을
  붙인다. 확정본이 오면 재채점한다.
- **판본 확인**: 채점 전에 대상 문서 헤더의 판본 표기를 확인한다. 현재 저장본이 유일 기준이다.
- 통계적 유효성을 주장하지 않는다 — 표본이 작다. [[tinytroupe-experiments]] 참조.
