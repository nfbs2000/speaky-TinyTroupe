# EXECUTION-FLOW — 라이팅룸 팀 런 «은성제과» (2026-08-02)

교육용 전 과정 기록. 이 문서의 모든 "실행됨"은 실제 관찰된 Agent 스폰·메시지·반환을
근거로 하며, 시뮬레이션 산출물(독자 반응 등)은 SIMULATED로 표기한다.

## 1. 무엇을 만들었나

**한국어 단편소설 «은성제과»** (공백 포함 2,988자) — 28년 된 빵집의 마지막 2시간,
세 인물의 사소한 충돌. 주제 미지정 요청에서 출발해 쇼러너가 형식(단편)과 주제를
선정했다. 최종본: `05-final-manuscript.md`.

## 2. 팀 구성 (Claude Code 에이전트 팀 — 세션당 하나의 암묵적 팀)

| 역할 | 구현 | 로드한 지식 |

- 워커 5명 전원 동시 스폰 (읽기 전용 도구: Read/Grep/Glob). 파일 저장은 전부 리드가 수행.

## 3. 태스크 보드와 실제 흐름

```
#1 캐스트(persona-architect) ──→ #2 씬 플랜(scene-orchestrator) ──→ #3 초안(synthesist)
                                                            ┌── #4 독자 반응(analyst) ──┐
                                            #3 완료 ──→ 병렬┤                          ├──→ #6 최종 통합(리드)
                                                            └── #5 편집 노트(editor) ──┘
```

실행 순서 (전부 실제 관찰됨):
1. 브리프 확정(리드) → `00-brief.md`. 형식 후보 4개 비교 후 단편 선정.
2. 팀원 5명 스폰 + 태스크 보드 6건 + 의존성 배선. 대기 팀원들은 **선행 준비 작업**을
   자발 수행 (문체 기조, 배경 3안, 독자 로스터, 검토 체크리스트 — process/01~04).
3. 캐스트 시트 3인 반환 → 리드 검토·결정(비대칭 인지 승인 등) → `01-cast.md`.
4. 씬 플랜 반환 → 리드 승인 + 개정 1(촉발 계단 복원) 패치 → `02-scene-plan.md`.
5. 초안 v1→v2→v3 (메시지 교차로 3판) → 리드 실측·저장 → `03-draft.md`.
6. 병렬 검증: 독자 반응(v2 보고 + v3 재실행) → `04a`, 편집 채점 → `04b`.
7. 최종 표적 수정 5건 → 작가가 전부 적용한 최종판 반환 (도입부 신호는 자수 경고에
   맞춰 작가가 압축 개선, "만" 복원 충돌은 작가가 스스로 재판단해 수용) → 리드
   실측(2,988자) → `05-final-manuscript.md`. 리드의 문장 개입 0건.

## 4. 리드의 주요 재정 (판단 근거 포함)

| 재정 | 내용 | 근거 |
|---|---|---|
| 비대칭 인지 | 단골은 주인을 알고(이름까지), 주인은 단골을 부분 인지(얼굴/패턴) | 대칭이면 마지막 인사가 강제되어 신파·열린 결말 동시 위협 (워커 제안 채택) |
| 촉발 계단 복원 | 팥(명분 상실)→도장 카드(수단 상실)→정점 | 오케스트레이터가 자기 시트 오독을 발견·정정 — "예외 안 만듦"은 카드 거절을 만드는 성격 |
| 계절 = 여름 | 시트 우선, 씬 골격의 늦가을 기각 | 시트가 상위 문서, 습도 대사가 여름에 물려 있음 |
| 닫는 사물 = 철판 위 여덟 개 | 셔터는 소리·배경 처리 | 신파 차단 목록 "셔터 클로징 샷" 금지 |
| 동작 규칙 협소화 | 의미 지시 서술만 금지, 이유 없는 관찰 동작 허용 | 외부 초점에서 "독자만 아는 구조"의 유일한 전달 통로 확보 |
| 얹어주기 = 냉장고 우유 | 15년 전 우유의 무언의 반복 | 차민규의 우유 구매가 부인 가능성을 선확립 |
| 창가 아이 단서 = 영구 봉인 | 우유 결말과 양립 불가 | 독자 분석가 판정: 겹치면 즉시 신파 |
| 재고 감소 = 치우기/담기 | 판매로 처리 시 "손님 없음" 가정과 모순 | 에디터 발견, 워커가 "쟁반 담기" 제3안으로 구현 |

## 5. 검증 결과 (요약)

- **에디터 (04b)**: A 페르소나 8 (서동만9/윤경아8/차민규8, 인물별 최솟값 방식) /
  **B 자기일관성 10** (재고 12 = 담기6+구매3+정리3, 현금 12,000−8,000−1,500=2,500,
  시각·계절 전부 정합) / C 유창성 8 / D 브리프 적합성 통과. **must_fix 0건.**
- **독자 3인 (04a, SIMULATED)**: 목소리 구별 yes×3 (블라인드 복원율 0.84),
  신파 0건 (담백 2 / 밋밋 1), 완독 의사 3/3. 도장 카드 비트 만장일치 최고점.
  우유 결말 = "신파도 봉합도 아님" (받아들여지기를 기다리지 않는 퇴장이 결정적).

## 6. 이 런이 보여준 협업 패턴 (교육 포인트)

1. **워커의 자기 정정이 품질을 끌어올렸다.** 오케스트레이터는 자신의 시트 오독(카드
   폐기)을 발견해 계단 병치로 복원했고, 신시시스트는 자기 안(공간만으로 열기, 늦가을,
   씬 전 굽기)을 세 번 스스로 폐기했으며, 에디터는 자기 판정을 두 번 번복했다("한 달은
   더" 삭제 권고 철회 등). 페르소나 아키텍트는 1차 검증 0.55짜리 시트를 스스로 고쳐
   0.82로 올렸다.
2. **검증 기준을 초안보다 먼저 고정했다.** 독자 로스터·추출 필드·검토 체크리스트가
   전부 초안 도착 전에 확정됨 — "초안을 본 뒤 필드를 만들면 결과가 초안에 끌려간다"
   (분석가). TinyTroupe의 실험 지향 원칙의 재현.
3. **서로 다른 계기로 같은 것을 재는 이중 검증.** 에디터의 A-X(시트 준수)와 독자의
   블라인드 테스트(복원율)는 갈리면 그 자체가 정보가 되도록 설계됨.
4. **산술 회계가 서사 도구가 됐다.** 재고(시계), 현금(퇴장 동기), 도장 칸(감정의
   숫자 층위) — B차원 10점은 우연이 아니라 원장 관리의 결과.
5. **메시지 교차(race)가 최대 마찰원이었다.** 초안이 3판까지 간 것, 검증이 v2/v3에
   걸친 것 모두 비동기 메시지 순서 문제. 리드가 "현재 저장본 = 유일 기준"을 반복
   선언해 수습했다.

- **자수 예산**: 분량 상한 근처에서는 수정 지시에 항상 순증/순감 예산을 명기할 것.

  경계 조항에 따라 정정 — "실제 수행된 실행을 수행되지 않은 것으로 기록하는 것도
  위반"이라는 원칙이 실전에서 확인됨.

## 9. 증거 경계 선언

- 독자 반응·집계는 전부 **SIMULATED** — 실제 설문·인간 데이터가 아니다.
- 이 문서에 기술된 실행(스폰, 메시지, 반환, 태스크 상태)은 전부 세션에서 실제 관찰됨.
- 산출 원고는 창작물이며 사실 보도가 아니다. 등장인물·상호는 전원 허구.
- 사실성 미보증 항목(제빵 공정 시간, 적립 관행, 폐업 신고 기한·가산세)은 에디터
  경계 선언대로 검증되지 않았다 — 출판 전 사실 확인 필요.
