# 00 — 워크플로 런 설정 (tt-focus-group)

- 런 ID: 2026-08-02-focus-group-subscription
- 실행 방식: **동적 워크플로** (`.claude/workflows/tt-focus-group.js`) — 팀 런
  (2026-08-02-bakery-last-day, 스킬 오케스트레이션)과의 **방식 비교 실험**
- 메인 세션의 역할: 워크플로 호출자 + 완료 후 분석자. **실행 중 개입 불가** —
  이것이 팀 방식과의 핵심 차이이며, 이 기록의 관찰 대상이다.

## 자극(stimulus) 선정

**"동네 빵집 구독제: 월 3만 원을 내면 집 근처 개인 빵집에서 매일 빵 1개를 픽업할 수
있는 서비스. 빵집에는 고정 수입이 생기고, 구독자는 개당 값보다 싸게 빵을 얻는다.
당신은 구독하겠는가?"**

선정 근거: TinyTroupe의 대표 시나리오(제품 평가 포커스 그룹, Product Brainstorming /
Advertisement 노트북 패턴)에 부합하고, 찬반이 갈릴 만한 트레이드오프(선결제 부담,
매일 픽업의 구속, 동네 상권 지원 정서)가 내장되어 있으며, 직전 팀 런의 주제(폐업하는
동네 빵집)와 이어져 교육 자료로서 연속성이 있다.

## 호출 인자 (Workflow args)

```json
{
  "stimulus": "동네 빵집 구독제: 월 3만 원을 내면 집 근처 개인 빵집에서 매일 빵 1개를 픽업할 수 있는 서비스. 빵집에는 고정 수입이 생기고, 구독자는 개당 값보다 싸게 빵을 얻는다. 당신은 구독하겠는가?",
  "audience": "구매력·생활 패턴·동네 상권에 대한 태도가 서로 다른 한국 소비자 3인",
  "num_personas": 3,
  "steps_per_phase": 1,
  "objective": "각 참가자가 구독 의사를 최종적으로 밝혔는지, 그 이유와 조건은 무엇인지 추출하라.",
  "fields": ["would_subscribe", "conditions", "justification"]
}
```

- 단계(phases): 워크플로 기본 3단계 사용 — 경험·첫인상 공유 → 상호 반박·발산 → 최종 입장 수렴
- 예상 에이전트 수: 캐스트 1 + 턴 (3명 × 3단계 × 1스텝 = 9) + 추출 1 = **11**

## 이 기록이 답하려는 질문

1. 코드로 고정된 파이프라인은 실행 중 어떤 판단을 스스로 내리는가 (리드 재정의 부재가
   어디서 티가 나는가)
2. tiny-person-actor의 턴 연기가 TinyTroupe 해석 프로토콜(THINK→TALK→DONE, 시트 우선)
   을 지키는가
3. 팀 런에서 40여 회 메시지 왕복으로 했던 품질 관리가 워크플로에서는 무엇으로
   대체되는가 (schema 강제, 프롬프트에 박힌 규칙)
